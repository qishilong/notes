# App webview真机调试

## iphone设备

**调试网盘App的Webview需要用CI包或者Debug包。**

### 1. 准备工作
* **设备要求**：
    * Mac电脑（macOS 10.15.4或更高版本）
    * iPhone/iPad（iOS 13.4或更高版本）
    * Lightning/USB-C数据线

* **软件要求**：
    * Safari浏览器（Mac和iOS设备均需最新版本）


### 2. 启用iOS设备的Web检查器
1. 在**iPhone/iPad上**：

    * 进入`设置`>`Safari`>`高级`
    * 开启`Web检查器`选项

2. 在Mac上：

    * 打开Safari浏览器
    * 进入`Safari`>`偏好设置`>`高级`
    * 勾选`在菜单栏中显示"开发"菜单`

### 3. 连接设备并开始调试
1. 使用数据线将iPhone连接到Mac
2. 在iPhone上信任此电脑（弹出提示时点击"信任"）
3. 在Mac的Safari中：

    * 点击菜单栏的`开发`
    * 选择你的iPhone设备
    * 从列表中选择要调试的网页标签页

## 调试Android设备网页（流程上类似）
### 1. 准备工作
* **设备要求**：
    * Android 5.0或更高版本
    * USB数据线

* **软件要求**：
    * Google Chrome浏览器（Mac和Android设备均需最新版本）
    * 启用USB调试模式


### 2. 启用Android设备的USB调试
1. 在Android设备上：

    * 进入`设置`>`关于手机`
    * 连续点击`版本号`7次以启用开发者模式
    * 返回设置，进入`系统`>`开发者选项`
    * 开启`USB调试`

2. 连接设备时选择文件传输模式：

    * 连接USB后，在设备上选择`文件传输(MTP)`模式

### 3. 在Chrome中设置远程调试
1. 在Mac上：

    * 打开Chrome浏览器
    * 访问`chrome://inspect`
    * 确保勾选`Discover USB devices`

2. 在Android设备上：

    * 打开百度网盘或者浏览器

### 备注：如果无法正常连接Andriod设备，尝试以下方法

“Device information is stale” 这个报错，通常意味着 Mac 端的 ADB 守护进程（adbd server）缓存了设备的旧连接状态，但实际设备状态已经变了（比如授权记录、USB 模式或端口发生变化），二者对不上，导致 ADB 无法正常握手，手机也就弹不出授权框。

你反复尝试无效，说明简单的 `adb kill-server` 可能并未完全清除这些缓存，或者有其他进程干扰。我们可以按顺序彻底排查。

---

#### 1. 彻底杀掉所有 ADB 残留进程（关键）
Mac 上可能同时有多个 adb 进程（比如通过 Homebrew 安装的、Android Studio 自带的），普通的 `adb kill-server` 可能只杀掉一个。

- **第一步**：在终端执行：
  ```bash
  adb kill-server
  ```
- **第二步**：用系统命令强制结束所有 adb 相关进程：
  ```bash
  sudo killall -9 adb
  ```
  如果提示 “No matching processes”，说明确实没有残留，可以忽略。
- **第三步**：确认进程已清空：
  ```bash
  ps aux | grep adb
  ```
  应该只显示 grep 进程本身，没有其他 adb 进程。

---

#### 2. 重置 Mac 端的 ADB 配置目录
除了密钥，`~/.android` 目录下还可能有缓存文件、USB 设备信息等残留，需要一并清除。

依次执行：
```bash
# 备份原目录（可选，以防万一）
mv ~/.android ~/.android_backup

# 重新生成干净的配置目录（再次启动 adb 时会自动创建）
adb start-server
```
这会生成全新的 `adbkey` 密钥对和纯净的设置。完成后，目录结构大致如下：
```
~/.android/
├── adbkey          (新私钥)
├── adbkey.pub      (新公钥)
└── ...
```

---

#### 3. 手机端：彻底重置 USB 调试授权状态
即便你之前撤销过授权，手机端的 adbd 服务可能仍缓存了状态，需要强制刷新。

1. 打开 **设置 → 开发者选项**。
2. **先关闭 USB 调试**，等待几秒。
3. 点击 **“撤销 USB 调试授权”**（如果可点击，就点一下；如果灰色不可点击，说明已无记录，也执行一遍）。
4. **重新打开 USB 调试**。
5. **重启手机**（这步非常重要，能让 adbd 服务以最干净的状态启动）。

---

#### 4. 修正 USB 连接模式并重新连接
手机连接 Mac 后，默认模式有时会干扰 ADB 握手。

- 先用 **“仅充电”** 模式连接，下拉通知栏，点 USB 通知，**手动改成 “文件传输（MTP）”**。
- 等 Mac 识别设备后，在终端执行：
  ```bash
  adb devices
  ```
- 此时手机上应该会弹出“允许 USB 调试吗？”的授权框，勾选“一律允许”，点允许。

如果仍然报 stale 或没反应，再尝试以下额外操作：
- **换一个 USB 端口**（直连 Mac，不要用拓展坞）。
- **换一根支持数据同步的线**（有些线只能充电）。

---

#### 5. **终极方案：用无线调试绕过 USB 问题（Android 11 以上）！！！**
如果 USB 连接本身因硬件或驱动问题一直无法稳定 ADB，可以先用无线方式建立信任，有时能“激活”USB 调试。

1. 手机和 Mac 连到 **同一 Wi-Fi**。
2. 手机上：**设置 → 开发者选项 → 无线调试**，打开开关，点进入，选择 **“使用配对码配对设备”**，记下配对码和 IP 地址。
3. Mac 终端执行：
   ```bash
   adb pair <手机IP>:<配对端口>
   # 按提示输入配对码
   ```
   配对成功后，执行：
   ```bash
   adb connect <手机IP>:<连接端口>
   ```
   连接成功后，手机上的授权记录里就会多出一台 Mac，此时再插上 USB 线执行 `adb devices`，弹窗概率会大增。

---

#### 如果依然是 “device information is stale”
可以最后确认一下 `adb` 版本与手机系统是否存在兼容问题：
```bash
adb version
```
尝试升级到最新的 platform-tools：
```bash
brew upgrade android-platform-tools
```
并重复上述“杀进程-清目录-重启手机”的流程。

绝大多数情况下，通过「**强制杀进程 + 删干净 ~/.android + 手机重启**」这个组合，stale 错误都能解决，并成功弹出授权对话框。你按这个顺序试一次，反馈一下结果，我可以继续帮你排查。

# Chrome调试面板出现的三个按钮

![img](https://qiniucloud.qishilong.space/20260626153734445.webp)

这张截图出自 Chrome 浏览器的 **`chrome://inspect`** 远程调试页面，用于调试安卓设备上（这里是百度网盘 App）的 WebView 页面。

红框中的三个按钮作用分别如下：

### 1. `inspect`（检查 / 常规调试）
*   **作用**：这是最常用的按钮。点击它，会弹出一个独立的 **Chrome 开发者工具（DevTools）** 窗口。
*   **使用场景**：连接该 WebView 实例，进行**实时**的 DOM 结构查看、控制台（Console）日志查看、网络请求抓包、JavaScript 断点调试以及性能分析。
*   **注意**：点击后，你的手机屏幕上会弹出“允许 USB 调试”的授权提示，需要点击确认才能成功连接。

### 2. `pause`（暂停 / 启动时暂停调试）
*   **作用**：点击它后，浏览器会立即连接该 WebView，并在该页面**即将执行第一行 JavaScript 代码时，强制让 JavaScript 引擎进入“暂停”状态**（即 Pause on start）。
*   **使用场景**：**极其有用**。如果你需要调试 App 启动初期、页面初始化、或者很短时间就执行完的 JS 代码，普通的 `inspect` 往往等你打开了 DevTools，关键的代码早就跑完了。使用 `pause` 可以帮你卡住执行，让你从容地设置断点。
*   **提示**：执行后，开发者工具会在 `Sources` 面板中被高亮暂停，你点击“恢复执行”按钮（▶️）即可继续。

### 3. `inspect fallback`（备用调试 / 降级检查）
*   **作用**：尝试使用**备用或降级的调试协议**去连接该 WebView。
*   **使用场景**：当常规的 `inspect` 按钮失效（例如点击没反应、报错，或者 WebView 已经被销毁/关闭但列表还没刷新，亦或是该 App 使用了定制版内核导致协议不兼容）时使用。
*   **实际意义**：它是系统的“保底方案”。在某些情况下，连接 WebView 会非常耗资源或容易断线，点击这个按钮可能会强制重新建立一个新的调试会话，或者在页面处于 Background（后台）状态时尝试强行唤起调试。

---

**💡 实用小提醒：**
*   如果在电脑端点击这些按钮后，弹不出开发者工具页面，或者弹出来是空白的。建议尝试：
    1.  **解锁手机屏幕**，并保持在百度网盘这个页面的前台。
    2.  在手机开发者选项中，确保 **“USB 调试”** 已开启。
    3.  如果在 Android 14+ 系统上，需要在 USB 调试开启后，额外勾选 **“允许通过 USB 调试（安全设置）”**。
